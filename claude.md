# Project Specification: Tekken 8 Discord Bot & Web Admin Tournament Platform (Powered by Challonge API)

## 1. Project Overview
We want to extend an existing Python Discord Bot (currently handling basic moderation like user timeouts) into a full-featured Tournament Management Platform for Tekken 8.
The core tournament logic (brackets, brackets math, seeding, single/double elimination) will be offloaded to the **Challonge API**. 
Our platform will extend Challonge by tracking custom metadata specific to Tekken 8 (Characters used, In-game Tekken IDs) and linking them to Discord Profiles.

### Core Architecture
- **Shared Database:** A single SQLite database accessed by both the Discord Bot and the Web Backend.
- **Discord Bot (Python):** Player-facing interface. Handles registrations and result reporting without forcing users to create an external account.
- **Web Dashboard (Python - FastAPI or Flask):** Admin-facing interface. Used to create, configure, and monitor tournaments. Protected via Discord OAuth2 Login (Staff Only).
- **Frontend UI:** Barebones HTML/CSS for now (functionality-first). Aesthetic styling will be handled in a later phase.

---

## 2. Shared Database Schema (SQLite)
The database must keep track of tournament configurations and players' custom metadata.

### Table: `tournaments`
- `id` (TEXT, Primary Key): The Challonge Tournament URL/ID.
- `name` (TEXT): Name of the tournament.
- `status` (TEXT): Status of the tournament (`SETUP`, `REGISTRATION_OPEN`, `ACTIVE`, `FINISHED`).
- `rules_ft` (INTEGER): First To X format (e.g., FT2, FT3).

### Table: `participants`
- `discord_id` (TEXT, Primary Key): The unique Discord User ID.
- `discord_name` (TEXT): The user's Discord username (e.g., `Gamer#1234`).
- `tekken_id` (TEXT): The user's Tekken 8 In-Game Name (Optional/Fallback).
- `main_character` (TEXT): The Tekken 8 character selected during registration.
- `challonge_participant_id` (TEXT): The participant ID generated by Challonge when added to the tournament.
- `tournament_id` (TEXT, Foreign Key -> `tournaments.id`): The tournament they are currently registered in.

## 3. Discord Bot Features (Player Interface)
Integrate the following Slash Commands (`discord.app_commands`) into the existing Python bot code.

### Commands:
* `/iscriviti [personaggio] [nome_tekken (opzionale)]`
    * **Logic:** Checks if a tournament has `status = 'REGISTRATION_OPEN'` in the database. If yes, it creates a participant on Challonge via API using the user's Discord Name. Saves the `challonge_participant_id`, Discord ID, Tekken ID, and Character into the local database.
* `/report [tuo_score] [avversario_score]`
    * **Logic:** Allows a player to report their match score. The bot maps the Discord ID to the current active match on Challonge and submits the score via Challonge API. (Note: Simple conflict management or admin override will be added later).
* `/tabellone`
    * **Logic:** Returns a link to the public web bracket view.

## 4. Web Dashboard Features (Admin Interface)
Build a barebones, purely functional web server using **FastAPI** or **Flask** sharing the same SQLite database file as the bot.

### Authentication:
- Secure the `/admin` routes using **Discord OAuth2**.
- Restrict access to a predefined list of Admin Discord IDs or specific Server Roles.

### Pages & Routes (Functional HTML only, no styling):
* `GET /admin/dashboard`: Lists active/past tournaments and shows a button to create a new one.
* `GET /admin/tournament/new`: Form to create a new tournament. Fields: Name, Challonge Tournament Type (Single/Double Elimination), FT format (FT2/FT3).
    * **Submission Action:** Calls Challonge API to create the tournament, then inserts the entry into the local database with status `SETUP`.
* `GET /admin/tournament/[id]`: Detail view of a tournament. Allows the admin to change status to `REGISTRATION_OPEN` (enabling the bot command), trigger `/shuffle` and start the tournament, or manually edit/remove participants.
* `GET /torneo/[id]`: **Public View**. A barebones HTML structure fetching the tournament bracket via Challonge API and enriching it with local database data (rendering the Player's Discord Name, Tekken ID underneath if different, and an indicator or path for their character icon).

## 5. Instructions for Claude Code Execution
1.  **Analyze current bot:** Read the existing Python file to understand how the bot client/bot instance is initiated and where to add new Slash commands.
2.  **Database setup:** Create a script/module to initialize the SQLite database if it doesn't exist.
3.  **Challonge Integration Client:** Build a lightweight helper module/class using `requests` or `aiohttp` to communicate with the Challonge API v1 (`https://api.challonge.com/v1/...`) using credentials that should be loaded from environment variables (`CHALLONGE_USER`, `CHALLONGE_API_KEY`).
4.  **Implement Web Web App:** Create the backend routes for the Admin panel. Use basic HTML templates (`jinja2` or similar) with raw forms. **Focus heavily on data flow, database syncing, and API correctness. Ignore UI styling completely.**
